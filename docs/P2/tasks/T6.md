TASK, IN THIS ORDER

STEP 1, THE KILL GATE.

Compute the gate over the FULL UNSTRATIFIED 200,000-CANDIDATE POOL, not over T2's
frozen item set.

Why, because getting this wrong invalidates the gate silently: T2 draws its item
set by stratifying ON beta_c, with an explicit quota for the beta_c = infinity
control stratum. A divergence rate measured on that set is therefore a readout of
T2's quotas, not of the signal space. Stratify to oversample divergent items and
the rate goes up; widen the robust quota and it goes down. Neither movement says
anything about whether an informed adversary reorders the optimal signal in this
task, which is the only question the gate asks. The pool is the only item base on
which the rate carries that meaning. Report the rate on T2's frozen set as well,
clearly labelled sampler-dependent, so the two are never confused.

Compute TWO pooled rates over the pool, both of them, and report both:

  grid rate       |D(8)| / N            diverges at or below the grid endpoint
  existence rate  |D(infinity)| / N     diverges at ANY finite budget, i.e. the
                                        fraction of pool items with beta_c < infinity

THE KILL DECISION IS ON THE EXISTENCE RATE, not the grid rate. beta_c = infinity
means the adversary never reorders that item at any budget and the effect genuinely
does not exist there. A finite beta_c > 8 means the effect DOES exist and the
reporting grid is merely too short to show it. Gating on |D(8)| conflates the two
and would kill a real effect whose beta_c distribution happens to sit above 8. The
grid endpoint of 8 is a reporting convention completed by spec section 8.2 and
flagged there as awaiting author confirmation; it does not get to decide whether
Arms B and C run.

Also compute the per-tile rate r_t (manmade |O|=3, moves |O|=3, hold |O|=4,
size |O|=6), ordered by |O|, at BOTH beta = 8 and beta = infinity, and apply spec
section 7.2's gate disambiguation protocol. Spec 7.2 anchors its rates at beta = 8;
the preregistration's gate decides at beta = infinity, so apply the criteria to the
beta = infinity rates and report the beta = 8 rates alongside for comparison against
the spec. This anchor mismatch is a known open item (preregistration Appendix A.2,
item 7) awaiting a spec amendment. Do not resolve it by editing the spec.

Then take exactly one of three outcomes, per preregistration section 7.1:

  1. Existence rate < 0.10. KILL. The adversary effect is absent in this signal
     space. STOP, write up the negative result, and report to the author that Arms
     B and C must not run.
  2. Both rates >= 0.10. PASS. Proceed to Step 2 on the grid as specified.
  3. Existence rate >= 0.10, grid rate < 0.10. The effect is real and the grid is
     too narrow. NOT a kill, and NOT a reason to lower the threshold. Extend the
     divergence curve by appending 16, 32, 64 in order, stopping at the first point
     where |D(beta)| / N >= 0.10; report the rate at every point reached and which
     point stopped the extension. The extension applies to the divergence curve
     only; every other figure and table keeps the original grid. Hard ceiling at
     beta = 64, on interpretability rather than numerics: if the grid rate is still
     below 0.10 there, report that the effect exists but is reachable only at
     persuasion budgets with no plausible interpretation, and carry that as a stated
     limitation rather than as a kill.

The per-tile clean-negative reading is available only when the pooled existence rate
has itself failed. A per-tile pattern does not overturn a passing existence rate.

Emit a machine-readable gate record carrying: the pooled existence rate, the pooled
grid rate, N, the four per-tile rates at each of beta = 8 and beta = infinity, the
sampler-dependent rate on T2's frozen set, the spec version, the disambiguation
verdict, which of the three outcomes obtained, and, for outcome 3, the extended grid
points and where the extension stopped. T7 and T8 confirm the gate by reading that
record; absence of a recorded failure is not a pass.

Do not proceed past this step without an explicit pass or an explicit outcome 3.

STEP 4. What predicts a low beta_c? Regress or otherwise relate beta_c to item

STEP 5. Figures. At minimum: |D(beta)| versus beta; the beta_c distribution with the

distribution.
