## Note added 2026-09-09 by the T6 session. Two things T7 must not rediscover.

### 1. BINDING: `A`'s domain comes from `beta_c`, never from the sign of `ext_i`

v2.0 section 3.2 defines the domain by an equivalence:

> `ext_i > 0` if and only if `o*_infinity != o*_0`, which is exactly
> `beta_c(i) < infinity`. So `A` is defined precisely on the divergence set.

**The equivalence is true mathematically and false in float64.** On P1's frozen
1,000 it fails on exactly one item. A rival beats `o*_0`'s margin by less than
P1's D51 tie-break tolerance, so the tie-break keeps `o*_0` and `beta_c` is
`infinity`, while `1 - marg_norm(o*_0)` evaluates to `2.2e-16` rather than `0`.

Consequences, with the numbers, so this brief is self-contained:

- An implementation that takes `A`'s domain from `ext_i > 0` computes
  `A = (marg_norm(o) - marg_norm(o*_0)) / 2.2e-16` for an **adversary-robust**
  item, yielding a finite `A` of order `1e16`.
- **Section 6's `ext_i >= 0.02` floor does not catch it if the floor is applied
  after `A` is formed**, which is the natural order to write it in. `2.2e-16` is
  below the floor, so a floor applied first does catch it, but an implementation
  that forms `A` and then filters does not.
- A range check does not catch it either: `A` is legitimately signed and
  legitimately large-negative off the poles (see item 2 below), so `1e16` does not
  stand out from a distribution whose off-pole median is `-3.3`.
- The smallest genuine `ext_i` on the divergence set is `2.09e-04`, four orders of
  magnitude above `2.2e-16`, so the two cases separate cleanly. There is no
  tolerance to tune and none should be introduced.

**Take the domain from `np.isfinite(beta_c)`.** `src/t6_f0_headroom.py` does this
and its `--demo` asserts `A(o*_0) = 0` and `A(o*_infinity) = 1` on all 460
divergent items and `A` undefined on the other 540. Reuse that function rather
than writing a second one; `CLAUDE.md` treats a copied frozen computation as a
duplication bug.

### 2. `A`'s geometry, so a real result is not read as a bug and a bug is not read as a result

Measured on the frozen divergence set, `reports/T6_F0_headroom.md`:

- `A` is **near-bimodal**. Only the two poles carry `A` in `[0, 1]`: `A = 0` at
  `o*_0` on 470 option-cells, `A = 1` at `o*_infinity` on 439. The median over the
  841 off-pole option-cells is **-3.329**.
- This is because `A` divides by `ext_i`, whose median on the divergence set is
  `0.2313`. An option well below `o*_0` on `marg_norm` is arithmetically far
  negative. **Large negative `A` is normal and is not an error.**
- Pearson correlation between P1's salience-Bayes coordinate and `A` at the option
  level is `0.0061`; Spearman is `0.4777`. The two coordinates order options very
  differently, so a result on one does not transfer to the other.

**Do not report negative mean `A` as a finding.** F0 medians are negative for
every model on the ladder, and T6 tested whether anything survives once P1's own
far-side finding is accounted for: leave-one-item-out, predicting `A` from the
choice's position on P1's coordinate, the median residual is exactly `0` for all
seven models **and** for a uniform-random chooser, with no model skewing negative.
Negative `A` is a corollary of Paper 1 re-expressed on the margin coordinate, not
independent evidence that models are worse than the no-adversary optimum.

**Use medians, and report the value from the means beside them, as v2.0 section
3.2 requires.** A mean of per-item `A` is dominated by the off-pole tail. This is
the same ratio pathology P1 measured in `src/frontier_position.py`, and it bites
harder here than on P1's coordinate.

### 3. F0 baseline rates, already measured, for the replication check

`results/T6_F0_headroom.json` carries the F0 numbers per model on the divergence
set from P1's frozen `cond4`, so T7's F0 arm has a target to reproduce rather than
only a design. Per rendering, the share landing on `o*_0` runs `0.2739` to
`0.4228` against a chance rate of `0.2732` (mean of `1/|O|`); the share landing on
`o*_infinity` runs `0.0946` to `0.3239`, below chance for five of the seven. A
point mass at `A = 0` is therefore **not** evidence of Bayes-optimal behaviour,
which is exactly why section 3.3 puts every claim on excess over the marginal
null. `CTRL` is cross-family: per P1's D111 only choice-based rates are comparable
for it, never magnitudes.
